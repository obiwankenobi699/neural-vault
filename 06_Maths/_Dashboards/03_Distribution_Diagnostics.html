Tab 1 — Detect
How do you identify which distribution your data follows?
In a DS/ML interview, never say "I'll assume normality." These four visual tools are your evidence — use at least two before drawing any conclusion.
Choose a sample dataset to inspect →
Q-Q Plot Most important
Sample quantiles vs theoretical normal quantiles. Straight diagonal = normal. Every deviation tells you something specific about shape.
Histogram + KDE + Normal fit
Kernel density estimate (blue) vs fitted normal curve (yellow). Divergence between the two shows how non-normal your data is.
P-P Plot Body-sensitive
Empirical CDF vs theoretical CDF. Q-Q amplifies tails; P-P amplifies the central body of the distribution.
Log-Log Plot Power-law detector
log(rank) vs log(value). A straight line = power law (Pareto). Concave curve = normal/log-normal. Key tool for detecting heavy tails.
Statistical Normality Tests
H₀: data is normally distributed. Reject H₀ when p < 0.05. Always combine with visual checks — large n makes tests flag trivial deviations.
★ Interview: "How do you verify normality?"
Answer in three layers: (1) Visual — Q-Q plot first, then histogram + KDE. (2) Statistical — Shapiro-Wilk for n < 50, D'Agostino-Pearson for n 50–2000 (jointly tests skewness + kurtosis), K-S for n > 2000. (3) Descriptive — skewness ≈ 0, excess kurtosis ≈ 0, mean ≈ median ≈ mode.
Key caveat: "With n > 5000, any distribution will fail Shapiro-Wilk. Visual + descriptive carry more weight at large sample sizes."
Q-Q shape dictionary
✓ Normal
Points follow diagonal perfectly. No systematic S-curve or hockey-stick shape.
⤴ Right-skewed
Points curve above line at right tail. Income, prices, insurance claims.
⤵ Left-skewed
Points curve below line at left tail. Exam scores, age-at-death distributions.
↗↖ Fat tails
S-shape: below at left end, above at right. Leptokurtic — more extreme events.
★ Interview: "Q-Q vs P-P — when do you use each?"
Q-Q: superior for detecting tail behaviour — skewness, outliers, heavy tails show dramatically. Axes are in original data units, making deviations interpretable. Default choice.
P-P: superior for inspecting the central body. Less distorted by extreme outliers — useful when you care about fit quality in the majority of your data rather than extremes.
Rule: show Q-Q in every interview. If the interviewer asks how you'd detect a power-law specifically, mention the log-log plot.
Tab 2 — Transform
Mathematical transformations: what they do and when to use them
These transforms convert skewed distributions toward normality by changing the scale of the feature. They are monotonic — they preserve rank order — so they don't distort your data's meaning, only its shape.
What does "transforming toward normality" actually optimise?
📐Linearity — Linear regression assumes a linear relationship between X and y. A log-normal feature has an exponential relationship with y. Log-transforming it makes the relationship linear, so the model can fit it with a straight coefficient.
⚖️Variance homogeneity (homoscedasticity) — Skewed features often have variance that grows with magnitude. Transforms stabilise the variance across the range, making OLS estimates unbiased and efficient.
🎯Outlier compression — A value of 1,000,000 in a skewed feature has enormous leverage on regression coefficients. Log(1,000,000) = 14, which is in a reasonable range. Transforms compress the extreme tail.
📊Distance metrics (KNN, SVM, PCA) — Distance-based models measure closeness in feature space. A 1-unit change at the low end of a skewed scale should mean the same as 1 unit at the high end. Transforms normalise this interpretation.
📈Coefficient interpretability — After log transform, a 1-unit change in log(x) corresponds to a fixed percentage change in x (multiplicative interpretation), which is often more natural for economic or biological data.

Box-Cox λ value guide
λ = 0
→ log(x). Most common useful value. Fitted when data spans orders of magnitude.
λ = 0.5
→ √x. Count data, Poisson features (page views, transactions).
λ = 1
→ identity. Box-Cox found no improvement — data already near-normal.
λ = −1
→ 1/x. Very strong right skew. Rates and speeds (response time, throughput).
★ Interview: "Yeo-Johnson vs Box-Cox — which do you use by default?"
Box-Cox: T(x,λ) = (x^λ−1)/λ if λ≠0 else log(x). Requires strictly positive values.
Yeo-Johnson: piecewise — for x≥0 applies Box-Cox to (x+1); for x<0 applies Box-Cox to (−x+1) with exponent (2−λ). Works on all real numbers.

Default answer: Always use PowerTransformer(method='yeo-johnson') unless you can guarantee x>0. It handles zero-containing and negative features that Box-Cox would silently break on. The performance gain over Box-Cox when x>0 is negligible.
Critical: pt.fit(X_train) → pt.transform(X_train) → pt.transform(X_test). Never fit on X_test — that leaks test distribution into your pipeline.
Tab 3 — ML Pipeline
How transformations fit into a real ML pipeline
The full workflow: detect → decide → transform → train → compare. This is what you describe in a DS interview when asked about your feature engineering process.
1
Detect skewness in every feature
Run df.skew() or df.describe(). Flag any feature where |skewness| > 0.5 as a transform candidate. Values > 1 are strongly skewed, > 2 are severely skewed. Look at the histogram too — skewness alone doesn't detect bimodality.
2
Decide which transform to apply per feature
All positive + strong right skew → log(x). Count data / mild skew → sqrt(x). Has zeros or negatives → Yeo-Johnson (safest default). Don't know → let PowerTransformer auto-find the best λ via MLE.
3
Fit on X_train ONLY — then transform both splits
pt = PowerTransformer(method='yeo-johnson')
X_train_t = pt.fit_transform(X_train)
X_test_t = pt.transform(X_test) ← never fit_transform on test. Fitting on test data leaks the test distribution's statistics (mean, std, λ) into your model evaluation — a form of data leakage that inflates reported performance.
4
Standardise after transforming
Transforms fix shape (skewness). StandardScaler fixes scale (mean=0, std=1). Both matter for linear models, SVM, and KNN. Pipeline([('tx', PowerTransformer()), ('sc', StandardScaler()), ('model', LinearRegression())]) — use Pipeline to prevent leakage automatically.
5
Validate on residuals, not just R²
For linear models, check the residual Q-Q plot. If residuals are normal (straight diagonal), your transform worked and your p-values and confidence intervals are valid. If residuals are still skewed, try a stronger transform or a non-linear model.
What transformations actually optimise in a model
📉Reduces leverage of extreme values — A single value of 1,000,000 in raw income data pulls the regression line toward it. After log: log(1M)=14 vs log(50K)=10.8. The ratio is reasonable; the leverage drops dramatically.
📏Makes the linear assumption hold — If income has a log-linear relationship with house price, raw income gives a curved regression — the model is misspecified. Log(income) makes the curve linear, so OLS can actually fit it.
🔀Stabilises variance (homoscedasticity) — For Poisson count features, variance = mean. High values have more noise. √x stabilises this: Var(√X) ≈ constant. Heteroscedasticity inflates SE of coefficients → wrong p-values.
🏘️Improves KNN and SVM neighbourhoods — In a skewed feature, Euclidean distance is dominated by the tail. After normalisation, all parts of the feature space contribute equally to distance, so neighbourhood-based models find meaningful clusters.
🔄Note on tree models — Random Forest and XGBoost split on rank order (thresholds). A monotonic transform cannot change which point is greater than another. Therefore tree models are invariant to monotonic transforms. Box-Cox won't help XGBoost.

When NOT to transform
Tree models (RF, XGBoost, LGB)
Split on rank/threshold — completely invariant to monotonic transforms. Box-Cox changes nothing for XGBoost. Save compute, skip it.
Skip transforms
Neural networks
Can learn non-linear mappings internally. Standardise features (BatchNorm handles scale), but distributional shape is less critical. Log-transform of target variable (y) can still help.
Standardise yes Shape optional
Linear models, SVM, KNN, PCA
Most sensitive to distribution shape AND scale. Transform skewed features first, then standardise. |skew| > 0.5 → investigate. > 1.0 → transform.
Always transform
★ Interview: complete feature engineering answer
"My pipeline for numeric features: (1) df.skew() — flag |skew| > 0.5. (2) For positive-only → try log; for zeros → sqrt or log(x+1); for negatives → Yeo-Johnson. (3) PowerTransformer(method='yeo-johnson').fit(X_train), apply to both splits. (4) Then StandardScaler. (5) Fit model. (6) Check residual Q-Q for linear models — normal residuals validate the transform worked and that inference (p-values, CIs) is valid. For tree models: skip transforms 2–4, just handle missing values. For neural nets: standardise but distribution shape matters less."
